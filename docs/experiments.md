# 检索基准实验协议

## 输入与目标

CSV 列为 `query,document,relevant`，可选 `query_id`。同一 query_id 的候选构成一个检索组；缺省使用 query 原文作为组 ID。实验比较候选内的排序，不对完整语料库做近邻搜索。

限制：最多 3000 行；query 最多 2000 字符，document 最多 12000 字符；每组至少两个不重复候选、至少一个相关候选。relevant 为 0/1。至少两个查询才计算查询级 bootstrap。

英文按字母数字词项分词，中文按单字分词。该中文分词策略适合最小基线，不应声称优于成熟中文分词器或语义检索。

## 三种算法

1. **overlap**：查询不同词项与文档词项交集大小 / 查询不同词项数。
2. **TF-IDF cosine**：在去重后的所有候选文档上统计 DF。`idf(t)=log((1+N)/(1+df(t)))+1`，权重为词频乘 idf，再取余弦相似度。
3. **BM25**：`k1=1.5, b=0.75`，idf 为 `log(1+(N-df+0.5)/(df+0.5))`，采用标准词频饱和与文档长度归一化。

整个 CSV 的文档集合用于无标签语料统计；相关性标签不参与调参或训练。模型没有学习参数，结果仍依赖候选构造，不代表跨分布性能。

打分相同时按 document 的 SHA-256 排序；标签与输入行号不参与排序。

## 指标

- Recall@K：前 K 个候选中的相关数量 / 此候选组全部相关数量。
- MRR：每组第一个相关文档的倒数排名，然后对查询平均。这里是**全候选 MRR**，没有截断为 MRR@K。
- nDCG@K：二元相关性 DCG / 理想排序 DCG，折扣为 `1/log2(rank+1)`。
- 95% bootstrap 区间：以查询为单位、有放回重采样 400 次，固定种子 42；使用排序后约 2.5% 与 97.5% 分位点。它描述查询重采样变动，不能纠正数据集偏差；在极少查询上只能当作诊断。

逐查询结果与完整排序保存在 benchmark.json。报告表格和 metrics.csv 从实测结果直接生成，而不是从模型回复提取数字。

## 示例结果

附带的合成数据包含 6 个查询、24 行配对。默认 K=3，当前实现算得：

| 方法 | nDCG@3 |
|---|---:|
| overlap | 0.8844289327304549 |
| tfidf | 0.8333333333333334 |
| bm25 | 0.8333333333333334 |

这些数值只验证管线可运行；不支持“overlap 优于 BM25”之类的外推结论。真实任务应使用客户的查询和人工相关性标注，进一步加入全库检索、延迟、成本和答案质量评估。
