# 产品：ResearchOps 技术选型与验证工作台

## 具体创业项目

为正在开发企业知识库 / RAG 应用的 AI 小团队提供“可追溯技术调研 + 基准验证 + 决策报告”服务。客户不是购买一份泛泛的论文摘要，而是围绕具体约束回答问题：当前检索方案有哪些可实施基线，已有资料究竟支持哪些判断，在自己的查询样本上效果如何，哪些结论还不能下。

初始交付可采用私有化工作台加人工质量复核的方式。收费方案是待访谈验证的商业假设，不是已经接入的支付服务：项目制收取技术调研与评估服务费，或按团队空间与维护支持收取订阅费。首先与 3–5 个真实团队做小范围付费试点，记录投入时间、报告采用率与后续复购意愿，再确定价格。

## 客户完整操作路径

1. 创建账户和项目，写清业务背景、研究目标、约束。
2. 导入已有技术文档/论文摘要，上传人工标注的查询—候选文档 CSV。
3. 选择演示或真实模型模式，开始任务。
4. Planner 把需求拆成检索问题与纳入标准；Researcher 搜索资料和 arXiv 摘要；Analyst 提取带原文的论点、比较能力与边界。
5. 如存在适用的检索数据集，审批页展示具体数据、哈希和实验参数。用户可批准，也可拒绝并继续调研交付。
6. Experimenter 调用受控评估工具，实际计算指标，保存逐查询排序。Reviewer 检查引用、结论范围与实验局限，必要时要求 Analyst 返工。
7. Writer 交付技术决策报告。用户下载包含原文快照、实验输入、指标和过程记录的 ZIP，便于复核。
8. 用户依据报告改进查询样本、补充资料，再发起新任务；定期研究用于跟踪技术资料变化。

## 功能范围与边界

当前版本覆盖“需求输入到研究交付”全流程。实验领域明确限制为固定候选检索基准；通用研究主题支持资料调研，但不会虚构未实现的实验能力。

当前没有在线收款、发票、商业套餐扣费、组织共享项目或外发邮件功能。账户空间按用户隔离，适合单团队私有部署或早期服务交付。商业成交与收款由运营人员在产品之外处理，不把未接入支付网关的状态称为交易成功。

当前不执行任意生成代码，不自动租用 GPU，不向外部用户发消息，也不自动提交论文。增加这些能力需要单独实现作业隔离、资源计费和业务权限，而不是在一个 shell 工具上无限放权。

## 产品验收标准

- 能首次初始化、登录并保存项目；重启后数据仍存在。
- 能从零启动示例，实际经过审批、实验、评审返工并得到可下载报告。
- 每条证据能定位到任务固定的原文；资料库后续修改不改变已完成任务。
- 界面数值来自实际 API / 实验，不显示硬编码的“成功率”或虚构调用费用。
- 真实模式具备工具调用、观察、再决策的循环，有执行边界、有失败状态，不能无限消耗模型调用。
- 失败后能继续已完成检查点，用户能取消任务，权限隔离覆盖读写和导出。

## 首批客户验证的指标

研究目标到初版报告的耗时、研究者人工复核时间、被采纳的决策比例、被指出的错误引用比例、真实数据集上的实验复现率、任务失败后恢复成功率。业务层面还需验证客户是否愿意为“可复核的技术决策”付费，而不只看报告生成数量。
